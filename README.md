# LISTEN 文字起こし校正アシスト

LISTENの文字起こしエディタに、折りたたみ可能な校正バーを追加するChrome拡張機能です。Manifest V3に対応しています。

## インストール

1. ZIPを展開します。
2. Chromeで `chrome://extensions/` を開き、「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」を選択します。
4. **manifest.jsonが入っているlisten-proofreaderフォルダー**を選びます。
5. LISTENの文字起こしエディタを再読み込みします。

通常のエピソードページにはバーを表示しません。拡張機能を更新した場合も、拡張機能一覧の再読み込みボタンを押した後、LISTENのタブを再読み込みしてください。

## 段落へのジャンプ

- **次の未分離**：話者の選択値が `-1` の段落へ移動します。
- **次の文字数異常**：下限未満、または上限超の段落へ移動します。
- **次の短い段落／次の長い段落**：短い段落、長い段落をそれぞれ巡回します。
- 初期値は**5文字未満／200文字超**です。下限と上限はバー内で変更でき、設定は保存されます。
- 空白・改行を除いたUnicodeコードポイント数を数えます。空の段落も短い段落に含みます。絵文字の組み合わせは複数文字になる場合があります。
- 段落をクリック・編集している場合はそこから次へ進みます。マウスホイール等で移動した場合は現在の画面位置から巡回します。最後まで進むと先頭に戻ります。
- 対象段落を青い枠で示します。話者変更・編集・結合・分割後は対象を再計算します。

## CSVによる置換候補の入力

1. **CSV読込**で、1列目「誤字」、2列目「修正案」、3列目「備考」のCSVを選びます。
2. **次の候補**で最初の候補を表示します。LISTENの既存の一括置換パネルが開き、「置換前」「置換後」に入力して「検索」を押します。
3. 置換後の入力欄の下に、候補番号と備考を表示します。
4. 検索結果と備考を確認して、LISTENの**すべて置換**を押します。
5. 再度**次の候補**を押すと次の行へ進みます。**前の候補**で戻れます。最後の候補では次へ進むボタンを無効にします。

「次の候補」は置換を実行しません。候補を飛ばしても構いません。CSVを読み直すと最初からになります。CSV解除は候補と備考を消し、既存フォームの入力内容はそのままです。

LISTENの一括置換は**段落の本文だけでなく、チャプター名とサマリーにも適用**されます。「文字起こし辞書に追加する」はLISTEN上の現在のチェック状態を使います。必要に応じて確認してください。CSV候補を入力すると、正規表現モードは解除して通常の文字列検索にします。

### CSVの仕様

```csv
誤字,修正案,備考
カムオンシェシェ,カムオン・シェシェ,団体名の表記を確認
金湖さん,金子さん,人名は音声と照合してください
不要な語句,,空欄の修正案は削除候補です
```

- UTF-8（BOMの有無を問わない）とShift_JISに対応。最大5MBです。
- ヘッダーは省略可能です。上記の日本語名、「置換前／置換後」「修正前／修正後」、`before／after` を判別します。
- 備考は省略可能です（2列でも可）。修正案の空欄は削除として入力します。
- 誤字が空欄の行と空行は除外します。誤字の前後の空白は、LISTENの検索仕様に合わせて除きます。修正案の空白は保持します。
- コンマ、引用符、改行を含むセルは通常のCSV規則で引用してください。例えば `"名前,表記"`、`"引用符""付き"`。閉じていない引用符や列数の不一致はエラーにします。
- 不正なCSVを読んだ場合、以前読み込んだ候補を保持します。
- 添付のexample.csvは形式を示す例です。修正内容は実際の音声と照合してください。

### 校正用CSVファイルの作成方法

ChatGPTなどAIの拡張機能をインストールし、LiSTENのエピソードページで次のプロンプトを実行してみてください。

> このページの文章はポッドキャストの文字起こしです。誤字・誤変換と思われる箇所をリストアップし、1列目に誤字、2列目に修正案、3列目に備考を記載したCSVファイルにまとめてください

最近のAIであればCSVファイルがそのまま出力されると思います。

### ローカルAIで生成して読み込む（Ollama / LM Studio）

初期状態ではこの機能は無効で、校正バーにAIボタンは表示しません。

1. OllamaまたはLM Studioに、日本語の校正に使用するモデルをインストールし、ローカルサーバーを起動します。
2. Chromeの拡張機能一覧から、この拡張機能の「拡張機能のオプション」を開きます。
3. 「ローカルAIによる誤字候補の生成を有効にする」にチェックし、接続方式を選択してサーバーのアドレスを入力します。Ollamaの標準値は `http://localhost:11434`、LM Studioは `http://localhost:1234` です。LM Studioでも `/v1` は入力しません。
4. 「インストール済みモデルを取得」を押し、指定アドレスへの接続を許可します。取得したモデルを選び、「設定を保存」を押します。
5. エディタの校正バーに表示される「AI候補生成」を押します。現在のURL末尾の `transcript_editor` を `transcript.txt` に置き換えて文字起こしを取得します（クエリとフラグメントは除外）。
6. 文字起こしを約3,000文字ずつ校正し、結果を「誤字／修正案／備考」のCSVに変換して読み込みます。「次の候補」で検索結果を確認し、必要な候補だけ置換してください。

Ollamaの [モデル一覧API](https://docs.ollama.com/api/tags) と [チャットAPI](https://docs.ollama.com/api/chat)、LM Studioの [モデル一覧API](https://lmstudio.ai/docs/developer/openai-compat/models)（`/v1/models`）と [チャットAPI](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)（`/v1/chat/completions`）に対応しています。LM Studioでは [JSON Schemaによる構造化出力](https://lmstudio.ai/docs/developer/openai-compat/structured-output) を使用します。Ollamaのクラウドモデルとして示されたモデルは一覧から除外します。文字起こしは生成ボタンを押したときだけ指定サーバーに送信します。AIアドレスは `http(s)://ホスト:ポート` の形式で、パスは指定できません。Chromeの接続権限は設定画面で指定したホストに対してのみ要求します。

LM StudioではDeveloper画面からサーバーを起動してください。一覧にはサーバーが公開しているモデルを表示します。全ダウンロード済みモデルを選ぶにはJust-In-Timeロードを有効にしてください。テキスト生成と構造化出力に対応するモデルを選択し、約3,000文字の入力を処理できるコンテキスト長をLM Studio側で設定してください。認証必須のサーバーには未対応です。接続方式またはアドレスを変更した場合は、モデル一覧を再取得してから保存してください。以前の接続方式が保存されていない設定はOllamaとして扱います。

取得するのはLISTEN側の `transcript.txt` です。エディタの未保存の変更が反映されていない場合があります。AIが返した候補のうち対象の本文に存在しない誤字、修正前後が同じ候補、重複する候補を除外します。長い文章の分割位置をまたぐ誤字は見落とす場合があります。生成中は候補の読み込み・移動を止め、失敗時や候補なしの場合は以前の候補を保持します。設定変更や画面切り替え時は生成を中断します。校正バーのステータス欄に処理状況を表示し、置換の自動実行はしません。

## 配置とデータ

校正バーはタイトルの下、サマリーの上に配置し、スクロール時は画面上部に留めます。下部のプレーヤー、同期状態、一括置換ボタンを覆う新たな固定ボタンは追加しません。既存のTailwindクラスを使い、ダークモードにも対応しています。「校正 ▾」を押すと詳細欄を折りたためます。

CSV候補はそのタブのメモリ内だけで扱います。手動で読み込んだCSVは送信しません。ローカルAIを使用する場合だけ文字起こしを設定したサーバーへ送信します。再読み込み時にはCSVの再選択またはAIでの再生成が必要です。文字数設定、折りたたみ状態、AI機能の有効無効・接続方式・アドレス・モデルをchrome.storage.localに保存します。置換を実行した内容の保存はLISTENの通常の動作に従います。

## 対応構造と検証の範囲

2026年10月5日に提供されたエディタHTMLの `.segment-row[data-segment-index]`、`[x-text="seg.text"]`、`[x-ref="replaceBeforeInput"]`、`[x-model="replacementString"]` を使用しています。編集中は段落内の表示中のtextareaの値を優先します。入力イベントを通してLISTEN側のモデルを更新し、既存の検索ボタンをクリックします。

添付HTML内の333段落と一括置換の要素を確認し、CSV解析、段落巡回、文字数判定、候補入力と検索クリックの処理を模擬DOMを使った18項目のコードテストで確認しています。ブラウザ起動・ローカル画面へのアクセスが環境の制限で使えず、実際の表示、Alpineとの本番連携、ログインしたLISTEN上での置換・保存は未確認です。LISTENのHTMLやクラス構造が変更された場合は調整が必要です。

Node.jsがあれば、拡張機能フォルダーで `node tests/unit.cjs` を実行してコードテストを再実行できます。追加パッケージは不要です。
ローカルAIのURL変換、両方式の通信、分割、応答検証、CSV変換は `node tests/local-ai.cjs`、設定の移行・切り替え・保存は `node tests/options.cjs` で検証できます。Ollama・LM Studioの実サーバーやChromeでの接続許可・画面表示は別途確認が必要です。
